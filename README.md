# Форма для леденцов

Лендинг с каталогом товара, информационными страницами, формой заказа и отдельной страницей 404.

Проект размещается на [Layero](https://layero.ru/) как обычное Next.js-приложение с серверным запуском. Статический экспорт и папка `out` не используются.

## Требования

- Node.js `>=22.13.0`
- npm
- аккаунт на [Layero](https://layero.ru/) для production-деплоя

## Локальный запуск

Установка зависимостей:

```bash
npm ci
```

Запуск dev-сервера:

```bash
npm run dev
```

Сайт будет доступен по адресу `http://localhost:3000`.

Проверка production-режима:

```bash
npm run build
npm start
```

`npm run build` создаёт внутреннюю папку `.next`, а `npm start` запускает Next.js-сервер. Папка `out` проектом не создаётся и не используется.

## Деплой на Layero через GitHub

Это рекомендуемый способ публикации проекта.

### 1. Подготовить репозиторий

Убедитесь, что в GitHub загружены:

- `package.json`;
- `package-lock.json`;
- `src/`;
- `public/`;
- `next.config.ts`;
- `tsconfig.json`;
- `price.ts`.

Не нужно загружать:

- `node_modules/`;
- `.next/`;
- `.env` и `.env.*`;
- локальные логи и временные файлы.

Они исключены через `.gitignore`.

### 2. Создать проект в Layero

1. Откройте [Layero](https://layero.ru/).
2. Создайте новый проект.
3. Подключите GitHub и выберите репозиторий `tanhiowyatt/SiteLed`.
4. Выберите production-ветку, обычно `main`.
5. Оставьте автоматическое определение Next.js или укажите Node.js 22 в настройках проекта.
6. Запустите первый деплой.

Layero заберёт код из репозитория, установит зависимости, выполнит сборку и запустит приложение. После успешной публикации сервис выдаст адрес проекта в домене Layero.

### 3. Подключить домен

После первого деплоя Layero выдаст адресу проекта технический домен платформы. Если нужен собственный домен, добавьте его в настройках проекта — Layero покажет DNS-записи, которые нужно добавить у регистратора домена.

После обновления DNS проверьте:

- открывается ли главная страница;
- работают ли `/offer` и `/privacy`;
- открывается ли страница 404 для неизвестного пути;
- присутствуют ли security headers в ответе сервера.

Подробности о подключении репозиториев и доменов находятся в [документации Layero](https://docs.layero.ru/).

### 4. Обновлять сайт

После изменения кода:

```bash
git add .
git commit -m "Update site"
git push origin main
```

Layero автоматически запустит новую сборку и опубликует обновлённую версию, если для проекта включён автодеплой.

## Деплой через Layero CLI

Если не требуется подключать GitHub-репозиторий, проект можно отправить из корня локального проекта:

```bash
npx layero@latest deploy
```

CLI загрузит исходники в Layero, где будут выполнены установка зависимостей, production-сборка и запуск приложения. Точный статус и логи деплоя доступны в панели Layero.

## Версия Node.js на Layero

В `package.json` указано:

```json
"engines": {
  "node": ">=22.13.0"
}
```

Layero поддерживает Node.js 20, 22 и 24. Для этого проекта рекомендуется Node.js 22. Версию можно выбрать в настройках проекта Layero или закрепить отдельным `.nvmrc`.

## Security headers

Security headers задаются в [next.config.ts](./next.config.ts) через `headers()`. Они применяются Next.js-сервером во время production-запуска.

Проверить их можно командой:

```bash
curl -I https://ваш-домен.example
```

В ответе должны присутствовать `Content-Security-Policy`, `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy` и `Strict-Transport-Security`.

## Структура проекта

- `src/app/` — страницы, layout, стили, форма заказа и 404;
- `src/components/` — переиспользуемые UI-компоненты;
- `src/hooks/` — React hooks;
- `src/lib/` — общие утилиты;
- `public/` — изображения и другие публичные файлы;
- `price.ts` — единый источник цены товара;
- `next.config.ts` — конфигурация Next.js и security headers;
- `package.json` и `package-lock.json` — зависимости и команды проекта.

## Цена товара

Цена хранится в корневом файле [price.ts](./price.ts):

```ts
export const PRODUCT_PRICE = 1290;
```

Чтобы изменить цену, достаточно поменять это значение. Главная страница, форма заказа и публичная оферта используют его автоматически.

## Форма заказа

Форма заказа пока является интерфейсным прототипом:

- заказ не записывается в базу данных;
- платёжный сервис не подключён;
- email-уведомления не отправляются;
- API доставки не подключено;
- после отправки показывается демонстрационное сообщение.

Перед приёмом реальных заказов нужно подключить backend, хранение заказов, оплату, email-уведомления и сервис доставки.
